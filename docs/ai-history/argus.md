# argus and holmesgpt history

History moved verbatim from `kubernetes/apps/ai/CLAUDE.md` on 2026-09-25 (#710); current state lives in that file.

## argus deployment notes (2026-08-19 onward)

- **argus** (`kubernetes/apps/ai/argus/`) — HolmesGPT-based SRE triage agent bridging to Discord. Bundles the official `holmes` chart as an unconditional subchart (`argus-holmes`, Holmes 0.39.0) plus a forwarder that receives Alertmanager webhooks, drives a Holmes investigation, and posts triage summaries to Discord (with optional bot-driven HITL approve/reject/revise buttons, degrading to REST-only if no bot token is set). Chart source is `j0sh3rs/argus`, a fork of `olivecasazza/argus` — forked 2026-08-19 to control the bundled Holmes version independently of upstream (which lagged several minor versions behind), tracked via a `GitRepository` pinned to `ref.tag` so Renovate's `flux` manager can bump it (the same pattern OpenViking used before its 2026-09-25 retirement).
  - LLM routing: `modelList.litellm.model: llamaswap/coder-large` (local only — `coder-large` resolves to `gpt-oss-20b`, 32k slot, since 2026-09-24 #701). It previously used the `debugging` combo, which leads with `cliproxyapi/claude-sonnet-5`; that was repointed on re-enable (#711) because argus is an automated consumer and the Anthropic lane policy above reserves Claude for interactive use against `http://omniroute.ai.svc.cluster.local:20128/v1` — the map key stays named `litellm` (matches `config.model: litellm`) purely to keep the diff mechanical; only the values changed, migrated off LiteLLM during the 2026-09-08 Phase 2 switchover. Omniroute's own `<prefix>/<model>` addressing replaces LiteLLM SDK's `litellm_proxy/` chaining prefix directly — that prefix was a LiteLLM-calling-LiteLLM convention Omniroute doesn't use or need. `argus`'s own chart default `modelList.auto` (pointed at a nixlab-specific omniroute gateway with `additionalEnvVars` referencing a secret that doesn't exist in this cluster) is overwritten field-by-field with the same Omniroute config rather than nulled — Helm's map merge does not delete a key on `null`, and Holmes validates every `modelList` entry's env-var substitution at boot, not just the selected one.
  - Toolsets: Kubernetes API state, `internet`, `bash` (built-in chart defaults) plus `prometheus/metrics` (VictoriaMetrics at `https://metrics.68cc.io`), `victorialogs` (`https://logs.68cc.io`), `grafana/dashboards` (in-cluster `grafana-service.monitoring.svc.cluster.local:3000` — `grafana.68cc.io` sits behind Authentik forwardAuth, which a Grafana service-account token can't clear), and a `pg_monitor`-scoped Postgres toolset (`postgres17-stats`) via the `holmesgpt_ro` role — cluster-wide stats only (`pg_stat_activity`, `pg_stat_replication`, `pg_locks`; `pg_stat_statements` isn't queryable yet, only `CREATE EXTENSION`ed in the `app` DB, not `postgres`), no per-database table access. `cilium/core`/`hubble/observability`/`helm/core` are deliberately NOT enabled — even `helm/core` alone overflowed `coder-large`'s 49152-token context budget and made every `/api/chat` request 500 (tracked as `home-ops-qv0.10`). The slot is now 32768 tokens (#701), so even the current toolset set needs re-checking against that budget once argus is live.
  - The standalone `holmesgpt` app (`kubernetes/apps/ai/holmesgpt/`) was retired 2026-08-19 once `argus-holmes` proved functionally equivalent and stable — one Holmes instance now, not two. Its `holmesgpt-secrets` Secret (`GRAFANA_API_KEY`, `POSTGRES_CONNECTION_URL`, originally `LITELLM_API_KEY`, since renamed `OMNIROUTE_API_KEY` during the Phase 2 switchover) relocated to `kubernetes/apps/ai/argus/app/secret-holmesgpt.sops.yaml`, same Secret name.

## Decision record: openclaw and argus (#711, 2026-09-24)

Both apps were fully wired but commented out of `kubernetes/apps/ai/kustomization.yaml`, and that config was drifting. Two live configs also pointed at Services that did not exist: Alertmanager's `discord` receiver webhooked `argus-forwarder`, and Flux's `openclaw` notification Provider/Alert posted to `openclaw:18789/hooks/flux`.

- **argus: re-enabled.** It is the Alertmanager triage path, and #712 (Hindsight incident memory for Holmes) builds on it. Its model moved from the `debugging` combo (Claude-first) to local `llamaswap/coder-large` to comply with the Anthropic lane policy. Check after rollout: `argus-forwarder` and `argus-holmes` healthy, Alertmanager's failed-send meta-alerts clear, and Holmes `/api/chat` fits the 32k slot.
- **openclaw: archived** to `archive/openclaw/`. No concrete autonomous use case today, and its memory still pointed at OpenViking, which Hindsight is replacing (#701). The Flux notification Provider/Alert moved with it (`archive/openclaw/notification-openclaw.yaml`), and so did its Alertmanager webhook stub and the `openclaw-sweep` GitHub label. Renovate ignores `archive/**`, so image bumps stop. **Revive** only with a concrete autonomous use case. When reviving, repoint memory to Hindsight rather than the `openviking` plugin, and restore the Flux notification.
- **Manual follow-ups (not in git):** revoke the `openclaw` Omniroute inference key and delete the `openclaw` OpenViking user. Reflector should remove the `openclaw-hooks-secret` copies in `monitoring` and `flux-system` once the source Secret is pruned; confirm that it did.

## atuin-ai-server deployment notes (2026-09-09 onward)

- **atuin-ai-server** (`kubernetes/apps/ai/atuin-ai-server/`) — self-hosted backend for Atuin's `[ai]` chat-over-shell-history feature (separate from the `atuin` sync server in `services` ns — different repo, different language, Elixir/Gleam not Rust). Standalone OpenAI-compatible-endpoint proxy; no incoming auth of its own, so LAN-only route (`atuin-ai.68cc.io`, traefik-internal-gateway, no forwardAuth — same plain-HTTP-client reasoning applied to llama-swap's own route; litellm is no longer a live peer to compare against, see the LiteLLM-removal history above). Routes through Omniroute (`http://omniroute.ai.svc.cluster.local:20128/v1`, `config.toml`) via a scoped inference key (`CHAT_API_KEY`, `atuin-ai-server-secrets`) — switched from LiteLLM 2026-09-09 as a Phase 2 switchover follow-up (this consumer was missed in the original repoint pass and discovered live-broken during later validation). Its one model entry (`default_model = "coder-large"`) points at Omniroute's `coding-fast` combo (currently just `llamaswap/coder-large`, single-tier — routine edits/quick Q&A, no subscription quota spent; `coder-large` now resolves to `gpt-oss-20b`, 32k slot, since 2026-09-24 #701), addressed as a bare combo name with no provider prefix; `alias`/`name`/`description` in `config.toml` are atuin-ai-server's own internal labels, never sent to Omniroute. Client points at it with `[ai] endpoint = "https://atuin-ai.68cc.io"` in `~/.config/atuin/config.toml`.

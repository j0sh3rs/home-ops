# llama-swap and llama-swap-apu history

History moved verbatim from `kubernetes/apps/ai/CLAUDE.md` on 2026-09-25 (#710); current state lives in that file.

## llama-swap (dGPU, bigboi-jms-01) — as of 2026-09-25

- **llama-swap** — local GGUF inference, Vulkan via `ghcr.io/mostlygeek/llama-swap:unified-vulkan-YYYY-MM-DD` (switched from the plain `vNNN-vulkan-bMMMM` tag family 2026-08-17 — only the unified image bundles `rocm-smi`, confirmed working post-switch: `rocm-smi --showmeminfo vram` reports real VRAM usage per pod). Pinned to `bigboi-jms-01` (Navi 48 dGPU = Radeon RX 9070 XT, RDNA4/gfx1201, device-id `0x7550`, 16 GiB VRAM, node-label `node.kubernetes.io/gpu-tier=dgpu`) via nodeAffinity. RDNA4 has a working Vulkan flash-attention path (b9803+) — `--flash-attn on` is beneficial here, NOT the RDNA2 no-coopmat case. The entry point for large/dense chat, reasoning, and coder models — `llm.68cc.io` route (Authentik forwardAuth) plus direct cluster-internal Service access. Chat-only as of 2026-08-17: the `always-on` group (embed/rerank/router) moved to `llama-swap-apu` (see below), and `qwen3-8b`, the earlier `reasoner` model (Qwen3-30B-Thinking, a different model than today's `reasoner` alias — see below, `reasoner` now points at `gpt-oss-20b`), `reasoner-agentic` (gpt-oss-20b), and `qwen3-14b` (retired once qwen3.6-27b was confirmed) were dropped — zero confirmed consumers anywhere in the repo. Since 2026-09-24 (#701, Hindsight) `gpt-oss-20b` is the sole chat model, always resident — no more `chat` swap group, since there is nothing left to swap between (see `configmap.yaml`). Init container pre-fetches GGUFs into the PVC. Model aliases (see `kubernetes/apps/ai/llama-swap/app/configmap.yaml` for source of truth):
  - `reasoner`/`reasoning`/`coder`/`code-large`/`coder-large`/`frontier`/`frontier-chat` → `gpt-oss-20b` (sole chat model since 2026-09-24, #701 — Hindsight's retain/reflect never wait on a model swap. Always-on, 5 parallel slots of 32768 tokens each (raised 4 -> 5 2026-09-24, #701 task 8b, alongside Hindsight retain concurrency 1 -> 2, to drain a backlogged retain queue), `ttl: 0`. `agentic-coder` and `qwen3.5-35b-a3b` disabled 2026-09-24, cannot co-reside with an always-on gpt-oss-20b — each needs ~13-14 GiB alongside gpt-oss-20b's ~11.5 GiB. Their aliases moved onto gpt-oss-20b so no consumer config changed; see `configmap.yaml` for the exact VRAM math.)

## llama-swap-apu (bee-jms-03) — as of 2026-09-25

- **llama-swap-apu** — second llama-swap instance, hard-pinned to `bee-jms-03` (Renoir iGPU, BIOS-expanded to 16 GiB dedicated VRAM — see `docs/superpowers/specs/2026-08-16-apu-light-inference-tier-design.md` for the bee-* hardware asymmetry). Always-on/non-exclusive, all models resident together:
  - `fast`/`small`/`router` → `qwen3-1.7b` (routing/classification; HA Assist's documented future hook, not yet wired in HA's config)
  - `embed`/`embedding` → **Disabled 2026-09-25** (only consumer was OpenViking, retired — commented out in `configmap.yaml`; history kept below). `qwen3-embed` (RAG embeddings; moved from `llama-swap` 2026-08-17 — small, latency-tolerant, doesn't need dGPU horsepower. openviking's `embedding.dense` is the live consumer, routed through Omniroute as `llamaswapapu/embedding`, not this endpoint directly — migrated from litellm during the 2026-09-08 Phase 2 switchover, see the openviking bullet below)
  - `vlm`/`vision` → **Disabled 2026-09-25** (only consumer was OpenViking, retired — commented out in `configmap.yaml`; history kept below). `qwen2-vl-2b` (Qwen2-VL-2B-Instruct Q4_K_M + f16 mmproj, ~2.2 GiB combined; added 2026-08-19 — first and only vision-capable model in the fleet. openviking's `vlm` was originally the live consumer here, routed through Omniroute as the `openviking-vlm` combo — as of 2026-09-18 `vlm` bypasses Omniroute entirely, talking directly to `gpt-5.6-luna` via a shim Service, and this model now serves only as the shim's local fallback target (image content or CLIProxyAPI failure) — see the openviking bullet below for the full direct-shim architecture. Fits the tier's 4.90 GiB free headroom measured with the other three always-on models loaded; vision encoders are kept at f16 since quantizing them measurably hurts vision quality. `ctx-size` bumped 8192 → 16384 same day: VikingBot inherits `vlm` as its general Agent model too, not just for image understanding — its memory-extraction/session-compression step sent an 8989-token prompt within hours of bot mode going live, 400'ing repeatedly and silently dropping that session's long-term memory extraction. **Bumped again, 16384 → 32768, 2026-09-17** after a real 45309-token OpenViking memory-extraction prompt was observed in production — see this file's openviking bullet below for how that observation led to the vlm leg bypassing Omniroute entirely via a direct-to-shim Service (2026-09-18), and `configmap.yaml`'s inline history on this `qwen2-vl-2b` entry for the exact headroom measurements: ~1.53 GiB free (9.6%) post-deploy, all four always-on models warm)
  - `rerank`/`reranker` → **Disabled 2026-09-25** (only consumer was OpenViking, retired — commented out in `configmap.yaml`; history kept below). `jina-reranker-v2` (jina-reranker-v2-base-multilingual Q8_0, ~305 MiB; added 2026-08-19 — openviking's real `retrieval.rerank` used to route through this endpoint via litellm's `infinity/`-provider `rerank` alias; as of 2026-09-09 it goes direct to llama-swap instead, bypassing any gateway entirely — see the openviking bullet below for why. Only model confirmed to score sanely through llama-server's rerank pooling: an open, unresolved llama.cpp issue (#16407) reports bge-reranker-v2-m3 and Qwen3-Reranker returning garbage scores via this same code path — do not substitute either without re-verifying score sanity first. Runs its own dedicated llama-server process (`--reranking --pooling rank`), never sharing a process with `qwen3-embed`'s `--embedding` flag — llama.cpp issue #21256: combining both on one instance forces `pooling_type=RANK` cluster-wide, breaking plain embedding calls on that process. jina-reranker-v2 itself moved off this tier to llama-swap (dGPU) 2026-09-10 (see below), so this tier's headroom figure now reflects the remaining four always-on models (`qwen3-1.7b`, `qwen3-embed`, `qwen3.5-4b`, `qwen2-vl-2b`) only, not five. Real on-node headroom via `rocm-smi` with those four loaded and `vlm`'s ctx-size at its current 32768 (bumped from 16384 2026-09-17 — see the openviking bullet below and `configmap.yaml`'s `qwen2-vl-2b` entry for the full history): ~1.53 GiB free (9.6%) post-deploy — genuinely little room left on this tier, do not add another always-on model without re-measuring)
  `coder-fim` (FIM autocomplete) was removed 2026-08-17 — its only consumer was Continue.dev, which is explicitly rejected (see "Decisions explicitly rejected" below). Cluster-internal only (`llama-swap-apu.ai.svc.cluster.local:8080`), no external route. `bee-jms-01`/`-02` are excluded (3 GiB stock dedicated VRAM, not worth targeting). Omniroute fronts both llama-swap instances (see the top-of-file overview) — argus and atuin-ai-server route through Omniroute instead, using its `<provider>/<model>` addressing scheme (`llamaswap/<model>`, `llamaswapapu/<model>`) rather than a mirrored alias list (there is no `kubernetes/apps/ai/litellm/` directory anymore).
